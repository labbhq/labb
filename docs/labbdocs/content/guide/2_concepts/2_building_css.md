The labb CLI detects the CSS classes your templates need from the attributes you set on components.


## The Problem

Tailwind CSS CLI scans your templates for CSS classes, but it can only detect **static** class names. When you use labb components with attributes like:

```html
<c-lb.button variant="primary" size="lg">Click me</c-lb.button>
```

Tailwind CSS CLI cannot determine that `variant="primary"` should map to the `btn-primary` class, or that `size="lg"` should map to `btn-lg`. This means these classes would be purged from your final CSS, causing styling issues.

## The Solution: Scan → Extract → Build

labb CLI solves this through a three-step process:

### 1. Template Scanning

The `labb scan` command analyzes your HTML templates to detect labb component usage:

```bash
labb scan
```

**What it does:**

- Searches for `<c-lb.component-name>` tags in your templates
- Parses component attributes and their values
- Maps attributes to CSS classes using component schemas

**Discovery Flow:**

1. **Local templates**: Scans `css.scan.templates` in your project
2. **Installed packages**: For each package in [`css.packages`]({% doc_url '4_references/1_config_yaml.md' 'guide' %}), the `components` templates of the groups you subscribed to (import-resolved, so no hardcoded paths)
3. **Combines results**: Merges all discovered templates for scanning

### 2. CSS Class Extraction

For each component found, the scanner:

1. **Identifies the component** (e.g., `button`, `card`, `modal`)
2. **Extracts attributes** (e.g., `variant="primary"`, `size="lg"`)
3. **Maps to CSS classes** using the component's schema:

    - `variant="primary"` → `btn-primary`
    - `size="lg"` → `btn-lg`
    - Base classes are always included (e.g., `btn`)

The extracted classes are written to a safelist under the generated, gitignored `.labb/` directory (`.labb/labb-component-classes.txt`):

```
/* Auto-generated by labb, do not edit */
/* Total classes: 15 */

btn
btn-primary
btn-lg
card
card-body
card-title
...
```

Alongside it, labb writes a single `.labb/labb.css` that pulls together everything from `css.packages`: the safelist (`@source`), each package's `literals` (`@source` globs for raw utilities), and each package's `imports` (inlined CSS, like labb's themes). Your `input.css` references all of it with one stable line:

```css
/* labb css - don't remove this line */
@import "../.labb/labb.css";
```

### 3. CSS Building

The `labb build` command uses Tailwind CSS CLI to build your final CSS:

```bash
labb build
```

**What it does:**

- Regenerates `.labb/labb.css` and the safelist from `css.packages`
- Processes your input CSS file (e.g., `static_src/input.css`), which imports `.labb/labb.css`
- Generates optimized output CSS with all required classes

## The Complete Flow

```bash
# 1. Scan templates and extract classes
labb scan

# 2. Build CSS with extracted classes
labb build

# (Or do both in one command)
labb build --scan
```

## Development Workflow

For development, you can use watch modes:

```bash
# Watch templates and rescan on changes
labb scan --watch

# Watch CSS and rebuild on changes
labb build --watch

# Development mode: concurrent watch + scan
labb dev
```

<span>`labb dev` is a shortcut for `labb build -w -s` (watch + scan mode).</span>

## Example

Given this template:

```html
<c-lb.button variant="primary" size="lg">Submit</c-lb.button>
<c-lb.card>
  <c-lb.card.body>
    <c-lb.card.title>Hello World</c-lb.card.title>
  </c-lb.card.body>
</c-lb.card>
```

The scanner extracts these classes:

```
btn
btn-primary
btn-lg
card
card-body
card-title
```


## Reactive props are not a limitation

A [reactive prop]({% doc_url '3_reactivity/3_reactive_props.md' 'guide' %}) (a prop prefixed with `$`, like `variant="$status:primary"`) used to look like the dynamic case the scanner cannot see. It is not. When `labb scan` meets a `$`-prop, it treats the runtime value as unknown and emits the classes for **every** value that prop can take, read from the component's schema:

```html
<c-lb.badge variant="$status:neutral">Active</c-lb.badge>
```

The signal can hold any of `variant`'s values at runtime, so the scan keeps them all (`badge-neutral`, `badge-primary`, `badge-success`, and the rest) in the built CSS. You never enumerate the values or safelist anything. This is why reactive props work with zero configuration: the class the signal resolves to is already there.

This applies to the `$`-prop form specifically, where labb knows the prop and its possible values. A plain `:`-bound value (`:variant="userVariant"`) is a Python object the scanner cannot inspect, so that case is still a limitation.

## Known Limitations

`labb scan` has limitations when dealing with dynamic content:

### 1. Dynamic Attribute Values

Django Cotton, which labb components are built on, allows you to set dynamic attribute values by adding a `:` colon before the attribute:

```html
<c-lb.button :variant="userVariant" />
```

Where `userVariant` is a Python object in the context. `labb scan` cannot resolve these dynamic values, and therefore cannot map them to the correct CSS classes.

### 2. Dynamic Component References

Django Cotton also allows dynamic component referencing via:

```html
<c-component is="component-name" />
```

`labb scan` cannot detect this dynamic component referencing at the moment, and therefore won't be able to extract the correct CSS mappings. *This is a potential future feature*.

## Workarounds

Two workarounds cover these cases:

### 1. Tailwind CSS Safelisting

Use one of the Tailwind CSS class safelisting methods in your `input.css` file. Safelisting tells Tailwind to include specific classes regardless of whether they're detected in your templates.

For example, in your `input.css`:

```css
@import "tailwindcss";
@source inline("btn-primary btn-secondary btn-lg btn-sm");
```

This ensures that `btn-primary`, `btn-secondary`, `btn-lg`, and `btn-sm` classes are always included in your final CSS.

For more details on safelisting methods, see the <a href="https://tailwindcss.com/docs/detecting-classes-in-source-files#safelisting-specific-utilities" target="_blank">Tailwind CSS documentation on detecting classes in source files</a>.

### 2. Limit Dynamic Usage

Where possible, limit the use of dynamically set attributes and components. Instead, use static attribute values the scanner can detect:

```html
<!-- Instead of this (not detected): -->
<c-lb.button :variant="userVariant" />

<!-- Use this (detected): -->
<c-lb.button variant="primary" />
```

The scanner then picks up every component class and includes it in the final CSS build.
